# Admin dashboard · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin area (overview, travellers, destinations, reports, audit log) that never exposes private
trip data, plus browser end-to-end tests — real API and demo mock agreeing.

**Architecture:** `middleware/admin.ts` (`requireAdmin`: 403 for non-admins); `routes/admin.ts`
(overview, users, destinations, reports, actions); `routes/reports.ts` (traveller-side reporting);
models `AdminAction`, `Report`; `Destination.hidden`. Frontend `features/admin/*` + `pages/AdminPage.tsx`
(tabs via `?tab=`), a Report button on public passports; Playwright under `frontend/e2e/`.

**Spec:** `docs/superpowers/specs/2026-11-03-admin-design.md`.

## Global Constraints
- Comment everything; no AI credit; commit to `main`; push only on the owner's word.
- Admin responses contain only: name, @username, email, joined, plan, blocked, trip count — never trips,
  journals, messages, money, budgets, locations, Kushal, questions (assert JSON in tests).
- Non-admins get 403 FORBIDDEN on every `/admin/*` route; signed-out 401.
- Every admin change writes `AdminAction { adminId, action, targetType, targetId, detail, at }`.
- Reports: reasons `'spam' | 'offensive' | 'impersonation' | 'other'`, note ≤ 300; 5/day per reporter;
  one open per reporter+target (409).

## Review Focus
1. A normal user calling any `/admin` route — 403 and no data. → Tasks 1–4.
2. An admin blocking another admin or themselves — 409, nothing changes. → Task 2.
3. A blocked user's existing session — refused at once (sessions revoked). → Task 2.
4. A hidden destination — gone from Explore and its page 404s, but trips already made still open. → Task 3.
5. Report spam (6th report in a day, duplicate open report) — 429 / 409. → Task 4.

---

### Task 1: Admin guard and overview
`requireAdmin`; `GET /admin/overview` → `{ travellers: { total, newThisWeek }, trips7d: { ai, cache, local }, today: { plans, regens, asks }, tolis, signups30d: { date, count }[], topDestinations: { name, trips }[] }`. Tests: admin sees counts from seeded users/trips/usage; a user → 403; signed out → 401; the JSON contains no trip titles or emails. Commit `feat(backend): admin guard and overview`.

### Task 2: Travellers and the audit log
`GET /admin/users?q=&page=` → `{ users: AdminUser[], total }` (`AdminUser { id, name, username, email, role, plan, blocked, joined, trips }`); `PATCH /admin/users/:id { blocked?, plan? }` (block revokes sessions; self/admins → 409); `GET /admin/actions` → last 100. Tests: search by each field; block → login refused and refresh refused; plan change; admin targets → 409; actions logged; no trip data in responses. Commit `feat(backend): admin — find, block and change plans of travellers, with an audit log`.

### Task 3: Destinations
`Destination.hidden` (default false); `GET /admin/destinations` (name, slug, region, bestMonths, places, trips30d, hidden); `PATCH /admin/destinations/:slug { hidden }`; public list excludes hidden, detail and places → 404; trips still open. Tests accordingly + survives `seedDestinations()` re-run. Commit `feat(backend): admin — hide a destination from Explore`.

### Task 4: Reports
Model `Report { reporterId, targetId, reason, note?, status: 'open'|'dismissed'|'actioned', action?, createdAt, decidedAt?, decidedBy? }`; `POST /reports { username, reason, note? }` → 201; `GET /admin/reports?status=open` (reporter and target as admin cards; the target's public bio); `POST /admin/reports/:id { action: 'dismiss'|'remove-content'|'block' }`. Account deletion removes their reports both ways. Tests: limits (6th → 429, duplicate → 409, self → 400); remove-content clears bio/avatar/privacy; block blocks; logged. Commit `feat(backend): reports of public passports and admin moderation`.

### Task 5: Website client and demo mock
`adminApi` + `reportsApi`, types, mock handlers with the same rules (demo admin `admin@tripwise.app`). Tests through the clients. Commit `feat(frontend): admin client and demo mock`.

### Task 6: Admin pages and the Report button
`/admin` with tabs Overview · Travellers · Destinations · Reports · Log; Report on public passports. Tests per tab + a non-admin sees "Admins only"; screenshots 1536/390. Commit `feat(frontend): admin dashboard and reporting`.

### Task 7: End-to-end tests
`@playwright/test` (dev), `frontend/playwright.config.ts` (webServer `npm run dev:mock -- --port 5199`, `channel: process.env.PW_CHANNEL ?? 'msedge'`), `e2e/traveller.spec.ts`, `e2e/admin.spec.ts`; `npm run e2e`. Commit `test: end-to-end browser tests for a traveller and an admin`.

### Task 8: Docs and wrap-up
README (features, roadmap, `npm run e2e`), backend README (admin + reports endpoints), spec status; suites, tsc, eslint, e2e; final review; commit; ask before pushing.
