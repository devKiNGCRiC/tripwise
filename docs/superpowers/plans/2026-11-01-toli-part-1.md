# Toli Part 1 — Toli and Deciding Together · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Groups ("Tolis") of Sahyatris can form around one shared trip (the Sahyatra), suggest and vote on
changes the leaders approve, decide destination/dates/transport by polls, agree a budget privately, plan with
TripWise inside the Toli, and talk in the Toli's own chat (Chaupal) with announcement mode and raise-hand
requests (Anurodh) — real API and demo mock agreeing.

**Architecture:**
- **Pure rules** (`backend/src/services/toliRules.ts`, no runtime imports — like `localPlanner.ts`) decide
  permissions, apply suggestions to a plan, tally polls and compute the group budget range. The API and the
  website's mock both import them (`@toli-rules` alias), so demo mode behaves exactly like the real API.
- **Backend:** one `Toli` model (members + roles inside), separate collections for suggestions, polls,
  budgets, messages, requests and activity; routes in `routes/tolis.ts` (+ `routes/chaupal.ts`). Trips gain an
  optional `toliId`; Toli members can read their Sahyatra.
- **Frontend:** `features/toli/` + pages `/tolis`, `/tolis/:id` (tabs) and `/toli/join/:token`; screens poll
  for updates (TanStack Query `refetchInterval`).

**Tech Stack:** as before — Express 5, Mongoose 8, Zod 4, Vitest/Supertest/mongodb-memory-server; React 19,
TanStack Query, MSW, Testing Library. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-01-toli-design.md` (Part 1 = items 1–9).

## Global Constraints
- Comment everything (file header + before every function/block); no AI credit anywhere; commit to `main`; push only when the owner says so.
- Errors are `{ error: { code, message } }`. **Non-members get 404 for anything about a Toli** (never reveal it exists); members acting above their role get **403 FORBIDDEN**; state clashes get **409 CONFLICT** (add `'CONFLICT'` to both `ApiErrorCode` unions and `FRIENDLY`).
- Names and copy: Toli, Sahyatri(s), Sahyatra, Sutradhar, Sah-Sutradhar, Sujhav, Chaupal, Anurodh, Tithi — each shown with a plain-English line where first seen (e.g. "Toli · plan trips together").
- Roles: `'sutradhar' | 'sah' | 'sahyatri'`. Exactly one `sutradhar` per Toli. Leaders = `sutradhar` + `sah`.
- Trip types: `'friends' | 'family' | 'college' | 'office'`; `college`/`office` start with `announcementMode: true`.
- Limits: 500 members per Toli; Toli name 2–60 chars; Sujhav note ≤ 280; message ≤ 2,000 chars; Anurodh "about" ≤ 200; poll 2–10 options, question ≤ 140; up to 4 photos per message (existing PhotoStore, browser-compressed like journals).
- Anurodh: one open request per person; 10 minutes after a decline before another; leaders can switch requests off per person; grants: `'one' | '30m' | '1h' | 'trip'`.
- Budget comfort: a private `[low, high]` INR per day per member; only the group overlap and how many answered are ever returned.
- Polling intervals: Chaupal 3 s while open; Toli screens 10 s; unread badge 30 s.
- Blocks: a user who blocked / was blocked by any member can't join or be added (404 as if unknown).

## Review Focus
1. Someone outside the Toli guessing its id or an invite of a revoked link — expect 404 everywhere (detail, trip, Sujhavs, polls, messages, budget). → tests in Tasks 2, 3, 7.
2. Approving a Sujhav after the plan changed underneath it (the stop it points at moved or was removed) — expect 409 CONFLICT and an unchanged plan, never an edit to the wrong stop. → Task 4.
3. The Sutradhar leaving or being "removed" — expect 409 until ownership is passed on. → Task 2.
4. A message sent twice after an offline retry (same `clientId`) — expect one message. → Task 7.
5. A member removed mid-poll or mid-budget — expect their votes and budget to drop out of tallies and ranges. → Tasks 5, 6.

### Task 1: Pure Toli rules (shared by API and mock)
**Files:** Create `backend/src/services/toliRules.ts`; Test `backend/test/toliRules.test.ts`.

**Interfaces — Produces:**
- `type ToliRole = 'sutradhar' | 'sah' | 'sahyatri'`; `type TripType = 'friends'|'family'|'college'|'office'`
- `isLeader(role: ToliRole): boolean`
- `canPost(member: { role: ToliRole; postUntil?: string | null; oneMessage?: boolean }, announcementMode: boolean, nowIso: string): boolean` — leaders always; others always when not announcement mode; else `oneMessage` or `postUntil > now`.
- `type SujhavChange` = `{ kind:'add-stop'; day:number; at:number; stop:StopDraft }` | `{ kind:'remove-stop'; day; index; title }` | `{ kind:'swap-stop'; day; index; title; stop:StopDraft }` | `{ kind:'move-stop'; day; index; title; toDay; toIndex }` | `{ kind:'retheme-day'; day; theme }` | `{ kind:'add-day'; theme }` | `{ kind:'change-transport'; day; index; title; mode }` (`title` = the stop's title when suggested, used to detect staleness; `StopDraft` = `{ title; description; startTime?; time }`)
- `applySujhav(days: DayLike[], change: SujhavChange, maxDays: number): { ok: true; days: DayLike[] } | { ok: false; reason: 'stale' | 'too-long' }` — never mutates input; stale when the stop at `day/index` no longer has `title`; `add-day` refuses past `maxDays`; removing the last stop of a day is allowed; transfers on the new last stop of a day are dropped.
- `tallyPoll(options: {id}[], votes: Record<userId, string[]>, memberIds: string[]): { counts: Record<optionId, number>; voted: string[]; notVoted: string[]; leading: string[] }` — only current members count.
- `budgetRange(entries: Record<userId, [number, number]>, memberIds: string[]): { answered: number; range: [number, number] | null; closest?: [number, number] }` — overlap = `[max lows, min highs]`; no overlap → `range: null`, `closest` = `[min highs, max lows]` (the gap to bridge).
- `defaultsForType(type: TripType): { announcementMode: boolean }`.
